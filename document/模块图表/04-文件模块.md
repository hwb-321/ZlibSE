# 文件模块

## 创建文件草稿

```mermaid
flowchart TD
    A[POST /api/files/draft] --> B[JWT 默认鉴权]
    B --> C{kind}
    C -- book --> D[查找当前用户未绑定正文文件]
    D --> E{存在?}
    E -- 是 --> R[返回已有文件信息]
    E -- 否 --> N[创建 stored_files 记录]
    C -- cover --> F[读取 Redis 未绑定封面集合数量]
    F --> G{数量 >= 5?}
    G -- 是 --> X[429]
    G -- 否 --> H{传入 fileHash?}
    H -- 是 --> I[按用户 + kind + hash 查找未绑定封面]
    I --> J{存在?}
    J -- 是 --> R
    J -- 否 --> N
    H -- 否 --> N
    N --> O[提交并刷新]
    O --> P{kind=cover?}
    P -- 是 --> Q[SADD Redis 未绑定封面 id]
    P -- 否 --> R
    Q --> R
```

## 申请上传会话

```mermaid
flowchart TD
    A["POST /api/files/{file_id}/upload-session"] --> B[JWT 默认鉴权]
    B --> C[查询 stored_files]
    C --> D{归属当前用户且未绑定?}
    D -- 否 --> X[403 或 409]
    D -- 是 --> E[获取 Redis upload-session 锁]
    E --> F{拿到锁?}
    F -- 否 --> Y[429]
    F -- 是 --> G[刷新数据库对象]
    G --> H{已上传或已进入解析?}
    H -- 是 --> Z[409]
    H -- 否 --> I{已有上传链接剩余时间 > 5 分钟?}
    I -- 是 --> R[返回已有上传会话]
    I -- 否 --> J{server-mock?}
    J -- 是 --> K[创建 mock 上传会话]
    J -- 否 --> L[创建或续签预签名上传 URL]
    K --> M[更新 upload_url/status/expires_at/object_key]
    L --> M
    M --> N[提交事务]
    N --> O[释放锁]
    O --> R2[返回上传会话]
```

## 确认上传完成

```mermaid
flowchart TD
    A["POST /api/files/{file_id}/complete"] --> B[JWT 默认鉴权]
    B --> C[查询 stored_files 并校验归属]
    C --> D[获取 Redis complete 锁]
    D --> E{已经 uploaded?}
    E -- 是 --> R[返回 alreadyCompleted=true]
    E -- 否 --> F{状态为 uploading 且 object_key 存在?}
    F -- 否 --> X[409]
    F -- 是 --> G{server-mock?}
    G -- 是 --> H[标记 uploaded + done]
    H --> I[用 mock 元数据写入 file_parse_results]
    I --> J[提交事务]
    G -- 否 --> K[调用对象存储 head_object]
    K --> L[更新文件元数据和 upload_status]
    L --> M{kind=book 且异步解析开启?}
    M -- 是 --> N[设置 parse_status=pending 并写入解析结果]
    N --> O[提交事务]
    O --> P[投递 Kafka 解析任务]
    P --> Q{投递失败?}
    Q -- 是 --> S[标记解析完成并写入 error_message]
    Q -- 否 --> T[保留待处理任务 id]
    M -- 否 --> U[设置 parse_status=done]
    U --> O
    J --> V[删除公开文件元数据缓存]
    S --> V
    T --> V
    V --> W[释放锁]
    W --> R2[返回文件信息]
```

## parse_status 状态机

```mermaid
stateDiagram-v2
    [*] --> not_started: 创建文件草稿

    not_started --> done: 封面文件确认上传
    not_started --> done: 正文文件确认上传但未开启异步解析
    not_started --> done: server-mock 直接写入解析结果
    not_started --> pending: 正文文件确认上传并投递解析任务

    pending --> processing: Kafka worker 开始处理
    pending --> done: Kafka 投递失败并记录错误

    processing --> done: 解析成功并写入结果
    processing --> done: 解析失败并记录错误

    done --> [*]: 可查询解析结果或用于创建书籍
```

说明：

- `not_started`：文件草稿刚创建，还没有完成上传。
- `pending`：正文文件已上传，解析任务已准备进入 Kafka。
- `processing`：异步解析 worker 已取到任务并开始解析。
- `done`：解析链路结束。成功时写入元数据；失败时写入 `error_message`；封面文件和未开启异步解析的文件也会直接进入该状态。

## bind_status 状态机

```mermaid
stateDiagram-v2
    [*] --> unbound: 创建文件草稿
    unbound --> bound: 创建书籍时采用正文文件或封面文件
    bound --> unbound: 删除书籍时解除文件绑定
    unbound --> [*]: 引用计数归零后删除文件记录和对象存储文件
```

说明：

- `unbound`：文件还没有被书籍使用，可以申请上传会话；未绑定封面会被加入 Redis Set 做数量控制。
- `bound`：文件已被书籍引用，不能再申请上传会话；作为正文或封面参与书籍详情和下载。
- 删除书籍时会先把关联文件标回 `unbound` 并递减引用计数；如果引用计数归零，会删除对象存储文件和 `stored_files` 记录。

## 获取下载地址

```mermaid
flowchart TD
    A["GET /api/files/{file_id}/download"] --> B[可选 JWT 鉴权]
    B --> C[通过一级缓存/Redis 读取公开文件元数据]
    C --> D{公开元数据命中?}
    D -- 是 --> E[使用缓存元数据]
    D -- 否 --> F[获取 Redis 文件元数据重建锁]
    F --> G[查询 stored_files]
    G --> H{ref_count > 0?}
    H -- 是 --> I[把公开元数据写入 Redis，TTL 带随机抖动]
    H -- 否 --> J[写入短 TTL 空值标记并继续本人未绑定路径]
    I --> I1[写入一级缓存]
    I1 --> E
    J --> K[查询 stored_files 判断本人未绑定访问]
    D -- 空值标记 --> K
    K --> L{当前用户拥有该未绑定文件?}
    L -- 否 --> X[404 或 403]
    L -- 是 --> M[使用本人文件元数据]
    E --> N{server-mock?}
    M --> N
    N -- 是 --> R0[返回固定 mock 对象 URL]
    N -- 否 --> O[记录 Redis 下载热点窗口]
    O --> P{热点窗口 > 阈值?}
    P -- 是 --> Q[尝试读取一级缓存/Redis 中的签名 URL]
    Q --> S{签名 URL 命中?}
    S -- 是 --> R[返回缓存签名 URL]
    S -- 否 --> T[生成预签名下载 URL]
    P -- 否 --> T
    T --> U{热点窗口 >= 阈值?}
    U -- 是 --> V[把签名 URL 写入 Redis，TTL 带随机抖动]
    U -- 否 --> R2[返回新签名 URL]
    V --> V1[写入一级缓存]
    V1 --> R2
```

下载接口返回的是 `downloadUrl / expiresIn / filename`。浏览器随后直接请求 `downloadUrl` 对应的 COS 预签名地址获取文件，后端只负责访问控制和签名生成，不转发文件内容。
