# 数据库格式说明

## 说明

本文档描述的是后续对象存储方案下，推荐采用的数据库结构。

设计目标：
- 保持结构简单，适合作为求职简历项目 demo
- 将书籍业务信息与文件存储信息拆开
- 文件表只保留最小必要字段
- `books` 到 `stored_files` 为单向引用关系

推荐保留 5 张表：
- `users`
- `books`
- `stored_files`
- `user_collected_books`
- `uploaded_books`

## 1. users

用途：
- 存储系统用户账号信息

字段：
- `id`
  - 类型：`Integer`
  - 主键
  - 建有索引
- `username`
  - 类型：`String(150)`
  - 用户名
  - 唯一约束
  - 建有索引
- `email`
  - 类型：`String(254)`
  - 邮箱
  - 默认值为空字符串
- `password_hash`
  - 类型：`String(255)`
  - 存储密码哈希值
- `is_superuser`
  - 类型：`Boolean`
  - 是否为管理员
  - 默认值为 `False`
- `created_at`
  - 类型：`DateTime`
  - 用户创建时间
  - 默认值为当前 UTC 时间

说明：
- 该表承担认证和权限的基础角色
- 当前密码保存为哈希值，而不是明文

## 2. stored_files

用途：
- 存储文件的对象存储定位信息
- 供书籍正文文件和封面文件引用

字段：
- `id`
  - 类型：`Integer`
  - 主键
- `bucket`
  - 类型：`String(100)`
  - 存储桶名称
- `region`
  - 类型：`String(50)`
  - 地域，例如 `ap-guangzhou`
- `object_key`
  - 类型：`String(500)`
  - 对象存储中的对象 key
- `original_filename`
  - 类型：`String(255)`
  - 原始文件名
- `content_type`
  - 类型：`String(100)`
  - MIME 类型
- `size`
  - 类型：`Integer`
  - 文件大小，建议按字节存储
- `etag`
  - 类型：`String(100)`
  - 对象存储返回的 etag
- `kind`
  - 类型：`String(50)`
  - 文件用途，例如 `book`、`cover`

说明：
- 这是面向 demo 的精简设计
- 不额外记录 `created_at`、`updated_at`、`status`、`uploaded_by`
- 只保留“能定位文件”和“能支撑展示”的必要字段

## 3. books

用途：
- 存储书籍业务信息
- 通过外键关联正文文件和封面文件

字段：
- `id`
  - 类型：`Integer`
  - 主键
  - 建有索引
- `title`
  - 类型：`String(200)`
  - 书名
- `author`（选填）
  - 类型：`String(100)`
  - 作者
- `isbn`（选填）
  - 类型：`String(20)`
  - ISBN
- `category`（选填）
  - 类型：`String(100)`
  - 分类
- `year`（选填）
  - 类型：`Integer`
  - 出版年份或书籍年份
- `language`（选填）
  - 类型：`String(50)`
  - 语言
- `book_file_id`
  - 类型：`Integer`
  - 外键，指向 `stored_files.id`
  - 正文文件 ID
- `cover_file_id`
  - 类型：`Integer`
  - 外键，指向 `stored_files.id`
  - 封面文件 ID，可空

说明：
- `books` 不再保存本地文件路径
- `books` 不再保存对象存储 bucket / key
- `books` 只负责书籍业务字段和文件引用

## 4. user_collected_books

用途：
- 表示用户与收藏书籍之间的多对多关系

字段：
- `id`
  - 类型：`Integer`
  - 主键
- `user_id`
  - 类型：`Integer`
  - 外键，指向 `users.id`
  - 建有索引
  - 删除用户时级联删除
- `book_id`
  - 类型：`Integer`
  - 外键，指向 `books.id`
  - 建有索引
  - 删除书籍时级联删除

约束：
- 唯一约束：`(user_id, book_id)`
- 约束名：`uq_user_book_collect`

说明：
- 一个用户不能重复收藏同一本书

## 5. uploaded_books

用途：
- 表示用户与其上传书籍之间的关系

字段：
- `id`
  - 类型：`Integer`
  - 主键
- `user_id`
  - 类型：`Integer`
  - 外键，指向 `users.id`
  - 建有索引
  - 删除用户时级联删除
- `book_id`
  - 类型：`Integer`
  - 外键，指向 `books.id`
  - 建有索引
  - 删除书籍时级联删除
- `uploaded_at`
  - 类型：`DateTime`
  - 上传时间
  - 默认值为当前 UTC 时间

约束：
- 唯一约束：`(user_id, book_id)`
- 约束名：`uq_user_book_upload`

说明：
- 一个用户对同一本书只保留一条上传关系

## 表关系

最终推荐关系如下：
- `books.book_file_id -> stored_files.id`
- `books.cover_file_id -> stored_files.id`
- `user_collected_books.user_id -> users.id`
- `user_collected_books.book_id -> books.id`
- `uploaded_books.user_id -> users.id`
- `uploaded_books.book_id -> books.id`

说明：
- `books -> stored_files` 是单向关系
- `stored_files` 不反向记录自己属于哪本书
- 这种设计更精简，适合 demo 项目

## 存储桶设计

推荐先使用“单桶 + key 前缀分类”的方式：
- 正文文件：`books/{yyyy}/{mm}/{uuid}.{ext}`
- 封面文件：`covers/{yyyy}/{mm}/{uuid}.{ext}`

推荐原因：
- 配置简单
- 结构清晰
- 接口实现简单
- 很适合当前项目规模

数据库中保留这些存储定位字段：
- `bucket`
- `region`
- `object_key`

这样即使以后更换桶，也不需要重构表结构。

## 总结

这份推荐数据库结构的核心思路是：
- `users` 管用户
- `stored_files` 管文件定位
- `books` 管书籍业务信息
- `user_collected_books` 管收藏关系
- `uploaded_books` 管上传关系

其中最关键的设计点是：
- 文件信息从 `books` 中拆出
- `books` 通过 `book_file_id` 和 `cover_file_id` 单向引用 `stored_files`
- `stored_files` 保持精简，只保存对象存储定位所需的最小字段
