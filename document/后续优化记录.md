# 后续优化记录

## 待修改：布隆过滤器启动预热

当前书籍布隆过滤器启动预热逻辑位于 `fastapi_app/services/bloom_service.py` 的 `warm_book_bloom`。

当前实现会一次性查询所有书籍 id：

```python
for (book_id,) in db.query(Book.id).all():
    bloom.add(str(book_id))
```

后续需要改为 MySQL 范围/游标分批查询，避免启动时一次性加载全部 id 到应用内存。

建议目标流程：

```text
last_id = 0
循环：
  SELECT id
  FROM books
  WHERE id > last_id
  ORDER BY id
  LIMIT batch_size

  如果本批为空，结束
  对本批 id 逐个 bloom.add(id)
  last_id = 本批最后一个 id
```

注意点：

- MySQL 可以按范围或 keyset pagination 批量查询 id。
- 布隆过滤器仍然必须逐个 id 添加，不能用一个连续范围直接替代 `bloom.add(id)`。
- `batch_size` 建议做成配置项，例如 `redis.bloom_warm_batch_size`。
- 预热完成后再刷新布隆过滤器可信窗口。
- 如果书籍量超过 `redis.bloom_expected_items` 很多，误判率会上升，后续可考虑定期重建或扩容配置。

## 当前已使用的优化技术

### 缓存优化

- 一级缓存：进程内 `TTLCache`，用于减少 Redis 读取。
- Redis 二级缓存：缓存书籍列表、书籍计数、书籍详情、用户 profile、收藏 id 快照、公开文件元数据、热点下载链接。
- 固定 key + 写后删除：业务写入 MySQL commit 成功后删除相关 Redis 和一级缓存，下一次读 miss 后回源并回填。
- 统一 TTL 随机抖动：JSON 内容缓存统一在 `cache_service.set_json / async_set_json` 写入 Redis 时追加随机 5 到 30 秒，降低大量 key 同时过期的概率；锁 key、限流窗口 key、热点窗口 key 等控制类 Redis key 不走该逻辑。
- 空值缓存：书籍详情和公开文件元数据不存在时会写入 `EMPTY_MARKER`，短 TTL 内避免重复打 MySQL。
- 一级缓存按前缀删除：用于删除书籍列表等多 key 本地缓存。

### 缓存穿透、击穿、雪崩相关

- 布隆过滤器：书籍详情接口用进程内布隆过滤器过滤明显不存在的 `book_id`。
- 布隆可信窗口：通过 `redis.bloom_trusted_ttl_seconds` 控制布隆过滤器的可信时长，避免长时间过度相信未重建的进程内布隆。
- 统一重建锁：书籍列表、书籍计数、书籍详情、收藏快照、默认鉴权 profile 回源、公开文件元数据、热点下载链接等“读缓存 miss 后回源并回填”的路径会使用 Redis 重建锁，避免同一热点 key 并发回源。
- 二次检查缓存：拿到重建锁后会再次读取缓存，减少重复重建。
- 等待重试：未拿到重建锁的请求会短暂等待并重试缓存。

### 查询与分页优化

- 书籍列表支持游标分页：`WHERE id < lastId ORDER BY id DESC LIMIT pageSize`。
- 保留页码分页兼容：未传 `lastId` 时使用 `OFFSET + LIMIT`。
- 分页参数上限：通过 `pagination.max_page_size` 和 `search.max_page_size` 限制单次查询规模。
- 搜索最小长度校验：通过 `search.min_query_length` 避免空查询或过短查询直接打数据库。

### 鉴权优化

- JWT 内携带 `auth_version`。
- MySQL 保存 `users.auth_token_version` 作为权威版本。
- Redis 保存 `user:{id}:auth_token_version` 用于默认鉴权快速校验。
- Redis / 一级缓存保存 `user:{id}:profile`，在认证版本通过后复用用户基础信息。
- 改密后递增 MySQL 版本并删除 Redis 认证版本、Redis profile、一级缓存 profile，使旧 token 失效。

### 并发与锁

- Redis 分布式锁使用 `SET NX EX`。
- 释放锁时用 Lua 脚本校验 lock value，避免误删其他请求持有的锁。
- 文件上传会话和上传完成流程使用 Redis 锁防止同一文件并发状态变更。
- 异步解析 worker 使用 Redis 锁避免同一文件重复解析。

### 文件与下载优化

- 对象存储客户端使用 `lru_cache` 复用，并在启动时预热。
- 公开文件元数据使用一级缓存 + Redis。
- 下载链接使用热点窗口识别：达到热点阈值后才缓存短时签名 URL。
- 热点访问窗口使用 Redis ZSET 记录。
- 下载链路中同步对象存储操作通过线程池执行，避免阻塞 async 路由。

### 异步处理

- 文件解析支持 Kafka 异步 worker。
- 上传完成后可投递解析任务，接口不必同步完成全部解析。
- Kafka Producer 有复用逻辑，避免每次投递都新建连接。

### 限流与降级

- 搜索接口支持按客户端 IP 做窗口限流。
- 限流优先使用 Redis 计数器。
- Redis 不可用时，搜索限流可退回进程内窗口。
- Redis 缓存不可用时，多数缓存读取会退化为数据库查询。

### 指标与观测

- HTTP metrics middleware 记录请求次数、状态码、耗时。
- SQLAlchemy 事件记录 SQL 次数、耗时和慢 SQL。
- 缓存读取记录一级缓存命中、Redis 命中、miss、空值命中。
- Redis 锁记录获取/释放成功、失败、异常。
- `/debug/metrics` 提供 Redis 聚合指标查看和清空。

### 数据库连接

- SQLAlchemy 连接池配置了 `pool_size`、`max_overflow`、`pool_recycle_seconds`、`pool_timeout_seconds`。
- 数据库 schema 通过 `python -m fastapi_app.init_db` 显式初始化；应用启动事件本身只预热书籍布隆过滤器和对象存储 client。
